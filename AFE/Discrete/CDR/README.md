# Discrete USB 2.0 CDR board (afe_cdr)

This is a prototype PCB of the PHY's clock and data recovery: the upper loop of the PLL-assisted CDR block. It implements the pins and behaviour of `AFE/veriloga/afe_cdr.va`:

- `CDR_DATA` (HS data: SMA pair or the FPGA's 480 Mb/s pattern)
- `CDR_EN` (control), `CDR_V_IN_2` (coarse tuning, from the PLL board's `CDR_CH_OUT_PLL`)
- `CLK_RX` (recovered 480 MHz clock) and `HS_RXD` (retimed data, J = 1)
- `CDR_CH_OUT` (loop control voltage)

The loop is built from standard parts:

- an Alexander (bang-bang) phase detector: two MC100EP29 dual D flip-flops (data on the rising, edge on the falling clock edge) and two MC100EP08 XORs for UP / DN;
- a fast "charge pump": BFR93A current switches into a 62 Ω load, fed through a 47 nH choke to a fine-tuning varactor (the model's proportional path);
- a discrete LC VCO: the PLL board's BFR93A Colpitts with two 1SV305 varactors (coarse from `CDR_V_IN_2`, fine from the driver);
- an NB6L14 1:4 LVPECL fan-out (two phase-detector clocks, CLK_RX, monitor), enabled by CDR_EN.

There is no integral path: the loop is first order, and a DAC trims the free-running frequency (calibration by the FPGA / PC tool).

It is an FMC LPC mezzanine. An AMD 7-Series FPGA on the carrier sends HS packets built by the repo's own `usb_tx_path` at 480 Mb/s, captures HS_RXD with CLK_RX (ISERDES, word clock CLK_RX / 8) and decodes it with the repo's `usb_rx_decoder8`, the PHY's HS decoder. Around them the FPGA adds:

- SYNC bits lost per packet, packet errors;
- a PRBS7 checker with an IDELAY eye scan;
- a CLK_RX frequency counter;
- the tuning DACs and the CDR_CH_OUT ADC.

A PC script drives it over UART.

Simulated (ngspice, transistor-level VCO and driver, behavioural 100EP logic): lock within 7 bits of the SYNC from any start phase and at −40 / 85 °C (uncalibrated, up to 2.4 % off), no sampling errors after SYNC, ≥ 577 ps margin to the data edges at ±10000 ppm and with 25 ps rms + 40 ps p-p jitter. Phase step 0.041 UI per decision (model T/16); no integral path.

| Directory | Content |
|---|---|
| `easyeda/` | EasyEDA Std schematic (`usb_cdr_board_sch.json`, 4 sheets), generated by `gen_schematic.py` from `cdr_parts.py` and LCSC library parts (`lib/`); `netlist.csv` |
| `bom/` | BOM (`cdr_board_bom.csv`) and JLCPCB assembly BOM (`cdr_board_bom_jlcpcb.csv`) |
| `sim/` | ngspice VCO (transistor level) and full-loop (XSPICE phase detector) simulations (`run_sims.py`, models in `models/`), `tables.py` (results, bang-bang figures) |
| `fpga/` | FPGA design (`rtl/`), Icarus testbench with `afe_cdr_bm.v` as the board (`sim/run_sim.sh`), XDC template, Vivado build script, Yosys check |
| `host/` | `cdr_host.py` (UART: status, settings, free-running calibration, DAC sweeps, SYNC-loss statistics, BER, eye scan) |
| `doc/` | Documentation, figures (`gen_figures.py`), Markdown → Word converter (`md2docx.js`) |

```sh
cd easyeda && python3 gen_schematic.py              # schematic JSON, netlist, BOM
cd sim && JOBS=3 python3 run_sims.py                # all simulations (~40 min on 3 cores); python3 tables.py
cd fpga/sim && ./run_sim.sh                         # FPGA testbench -> TEST PASSED
cd fpga && yosys -q -s synth_check.ys               # xc7 smoke synthesis
cd doc && python3 gen_figures.py && NODE_PATH=<npm dir>/node_modules node md2docx.js
```

To open the schematic in EasyEDA Std:

1. Open a new schematic.
2. Choose Design → *File Source* (the `<>` toolbar button).
3. Paste the contents of `easyeda/usb_cdr_board_sch.json` and click **Create New Document**.

The four sheets open as one schematic.
